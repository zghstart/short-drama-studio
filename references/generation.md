# 生成执行

## 能力与成本

按用户指定的供应商和模型执行。未指定时比较参考方式、人物表现、对白、时长、分辨率、画幅、费用和等待时间。名字相似不证明接口兼容。

记录准确模型 ID、查询日期、官方能力来源、参数和计价依据。不同分辨率、输入和输出计价项不能随意相加或任选一项当整片费用。折扣需要当前价格或活动证据，估算与实际账单分别记。

用户已授权制作并交由选型时，在已知范围内执行。规模或费用明显超出约束时，先准备可审阅方案并集中说明缺口。不切换到用户未选择的付费账户，不创建无关云资源。

## 任务状态

每个生成单元维护镜头 ID、请求和素材哈希、模型参数、本地状态、服务端 ID 和状态、最后检查时间、下载文件、实际媒体参数及验收结果。

参考过程：`planned → submitting → queued/running → succeeded → downloaded → reviewed`。
提交后失去响应且没有任务 ID，是结果未知，不是明确失败。

`zenmux.py` 在提交前写状态，并用排他锁防止同目录并发提交。收到 ID 后立即保存，再调用 `submit` 不会重发；用 `poll` 和 `download` 续跑。

| 情况 | 动作 |
| --- | --- |
| POST 超时或返回无法解释的响应 | 保留未知状态，核查供应商记录，不自动重发 |
| 排队或运行中 | 查询同一 ID |
| GET 临时失败 | 保留 ID 和最近有效状态，之后续查 |
| 明确参数错误或任务失败 | 按实际错误修正，新任务用新目录保留历史 |
| 成功但下载失败 | 继续下载原结果 |
| 文件已存在 | 校验文件和任务对应关系，不仅凭文件名宣布完成 |
| 声音或字幕问题 | 修相应音轨或图层，不重做无关画面 |

普通修复不必重复设置确认。确定失败、已有授权与合理修复范围内可继续；结果未知的提交先消除未知。

## 批量与交付

互不依赖、参考已准备好的任务可以并行；依赖上游尾帧、动作或参考声音的任务，等实际结果检查后再提交。

生成时长可留适量剪辑余量，不为统一段长让人物空等。最终长度以故事与真实音频为准；精确30秒的目标包括片头、片尾和转场。

保留原始输出与制作记录。原生分辨率、导出尺寸、源帧率和导出帧率分别记录。费用仅有接口或账单证据时才写成实测值。
